# V4.2S FORJA Agent Skills Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publicar e integrar a v1.0.0 do FORJA Development Pack com 12 skills, ciclo de vida Windows seguro, validação determinística e zero alteração funcional do SaaS.

**Architecture:** Um marketplace de repositório aponta para um plugin puro de skills. As 12 skills são concisas e roteadas por risco; scripts PowerShell compartilham funções determinísticas para instalação por tag, junctions, marketplace, estado atômico, atualização e rollback. Fixtures, CI, smoke tests, benchmark, três revisões e Codex Security fornecem evidência antes da release e da integração documental no FORJA.

**Tech Stack:** Markdown, JSON, PowerShell 5.1/7+, Git, GitHub Actions (`windows-latest` e validação portátil opcional em Ubuntu), Codex plugin/skill schemas oficiais.

## Global Constraints

- Repositório do pacote: `Pedroasz/forja-agent-skills`; branch: `feature/v1.0.0-foundation-home`; base: `7ce056cb2c03e2c643d298cf88bd3196eee4090e`.
- Versão estável: `1.0.0`; tag e release: `v1.0.0`; licença: MIT.
- Exatamente 12 skills; nenhuma dependência Node; nenhum MCP, connector, app ou hook.
- Windows com PowerShell 5.1 e 7+; caminhos pessoais são resolvidos em runtime e nunca versionados.
- Skills pessoais: `%USERPROFILE%\.agents\skills`; marketplace pessoal: `%USERPROFILE%\.agents\plugins\marketplace.json`.
- Nenhuma alteração em `index.html`, JavaScript/CSS/HTML funcional, service worker, PWA, assets funcionais, Supabase, dados reais, Vercel ou produção.
- Nenhum SQL remoto, `supabase db push`, `supabase db reset --linked`, `service_role`, deploy manual, force push, reset destrutivo ou limpeza destrutiva.
- Cada comportamento novo segue RED → GREEN → REFACTOR; cada skill é baselineada e forward-tested individualmente.
- Antes de cada push: executar todos os validadores disponíveis e identificar claramente qualquer checkpoint incompleto.
- Após cada checkpoint validado: commit pequeno, push imediato e atualização do mesmo draft PR.
- A implementação anterior no computador do trabalho não está disponível e não será utilizada.

## File Map and Interfaces

### Distribuição

- `.agents/plugins/marketplace.json`: catálogo de uma única entrada local para `./plugins/forja-development-pack`.
- `plugins/forja-development-pack/.codex-plugin/plugin.json`: identidade, versão, publisher, `skills: ./skills/` e interface; sem campos executáveis.
- `plugins/forja-development-pack/README.md`: visão compacta do plugin e das 12 skills.

### Skills

Cada um dos 12 diretórios listados nas Tasks 4–15 produz:

- `SKILL.md`: front matter + contrato obrigatório de 12 seções;
- `references/<topic>.md`: detalhe diretamente ligado, sem referências encadeadas.

### PowerShell

`scripts/ForjaSkills.Common.psm1` produz estas interfaces públicas:

```powershell
Resolve-ForjaPaths -CloneRoot [string] -> [PSCustomObject]
Assert-ForjaOrigin -RepositoryRoot [string] -> [string]
Assert-ForjaCleanTree -RepositoryRoot [string] -> [void]
Get-ForjaStableVersion -RepositoryRoot [string] -Version [string] -> [PSCustomObject]
Read-ForjaState -StatePath [string] -> [PSCustomObject]
Write-ForjaJsonAtomic -Path [string] -Value [object] -> [void]
Test-ForjaJunction -Path [string] -ExpectedTarget [string] -> [bool]
Set-ForjaJunction -Path [string] -Target [string] -> [PSCustomObject]
Update-ForjaMarketplace -Path [string] -PluginPath [string] -> [PSCustomObject]
Remove-ForjaMarketplaceEntry -Path [string] -> [PSCustomObject]
Invoke-ForjaValidation -RepositoryRoot [string] -> [PSCustomObject]
```

Os scripts públicos consomem somente essas funções e retornam exit code `0` em sucesso, diferente de zero em falha obrigatória.

### Tests

- `tests/Run-Tests.ps1`: harness nativo, cria sandboxes sob `$TestDrive`, imprime `PASS|FAIL`, conta testes e retorna exit code.
- `tests/trigger-cases.json`: prompts, flags e atributos observáveis.
- `tests/expected-routes.json`: risco, selected skills, approvals e prohibited actions por ID.
- `tests/fixtures/`: marketplaces, estados, repositórios Git e árvores de skill válidas/inválidas.
